# Audio test files

Files are named with the pattern: `[supplier]-[YYYYMMDD]-[optional_descriptive_string].[extension]`.

The descriptive string uses the same codes as the [2.2 image test files](../../2.2/image/README.md):

| Code | Meaning |
| ---- | ------- |
| **C** | Claim |
| **A** | Parent ingredient (acquisition) |
| **I** | Ingredient |
| **E-dat-** | Error: Hard binding hash mismatch |
| **E-sig-** | Error: Signature did not validate |
| **E-uri-** | Error: An assertion has been tampered with (URI hash mismatch) |

## CogProof files (`cogproof-20261029-*`)

Generated by CogProof with [c2pa-rs](https://github.com/contentauth/c2pa-rs) (0.92.0-dev) with [`tools/audio`](../../tools/audio). Each format has the same set of files:

* **C**: a 3-second 440 Hz sine tone, signed with a `c2pa.created` action (`algorithmicMedia`).
* **CA**: the C file at -6 dB. C is its parent ingredient, with `c2pa.opened` and `c2pa.edited` actions.
* **CAI**: as CA, with an unsigned 660 Hz tone mixed in as a component ingredient (`c2pa.placed`).
* **E-dat-CA**, **E-sig-CA**, **E-uri-CA**: copies of CA, each with one byte changed.

| Format | Embedding | Hard binding |
| ------ | --------- | ------------ |
| MP3 | ID3v2 `GEOB` frame | `c2pa.hash.data` |
| WAV | RIFF `C2PA` chunk | `c2pa.hash.data` |
| FLAC | ID3v2 `GEOB` frame | `c2pa.hash.data` |
| M4A | BMFF `uuid` box | `c2pa.hash.bmff.v3` |

Each bad file fails for one reason only. The flipped audio byte is outside the manifest store, and the E-sig and E-uri changes are in the active manifest, not the parent's. In the FLAC and M4A E-dat files the flipped byte falls in a compressed frame, so decoders may report one damaged frame.

Each file has a C2PA Tool style report in `manifests/<name>/manifest_store.json` and `manifests/<name>/detailed.json`, next to the file.

### Signing certificate

The files are signed (ES256, no time-stamp) with the c2pa-rs test certificate, valid until 2030-08-26 (`sdk/tests/fixtures/certs/es256.pub`). It is not on any production trust list, so validators report `signingCredential.untrusted` unless they are given its test root (`sdk/tests/fixtures/certs/trust/test_cert_root_bundle.pem`). The reports in `manifests/` were made with that root as the trust anchor.

### Regenerating

The generator needs ffmpeg (with libmp3lame) and c2pa-rs checked out at `../c2pa-rs-integration`, next to this repository (see `tools/audio/Cargo.toml`).

```sh
cd tools/audio
cargo build --release
python3 build.py --date 20261029
```

ECDSA signatures are randomised, so a rebuild produces different bytes with the same validation results.
